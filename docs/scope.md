# Stage 1の範囲と保証

基準はCCM v0.1 Draft 6と、ユーザーが指定したStage 1のP0 4項目です。既存workflowのスリム版への言及や、他仕様の構成変更をこの実装へ自動的に採用しません。

## 実装単位

| P0 | 実装する性質 |
|---|---|
| 公開スナップショット | 承認済みの公開構成、現在のAPI情報、同一版で不変のJSON本文を分離する。公開時に下書きを参照しない |
| API更新・削除の公開連動 | 更新・削除と公開版・公開要求を同じ原子的操作に含める。APIエラーと動画取得不能を区別する |
| 検証結果のD1記録 | 対象版・試行・両ファイル照合結果を記録し、保存失敗・古い結果・重複通知を扱う |
| 公開リビジョンの再検証 | 公開直前の最新版確認と試行ロックで、古い実行による後戻りを防ぐ |

初回だけは、既存データから新しい承認済み構成を明示的に作成します。旧 `snapshot_json` の内部形式やタイトル由来は推測しません。新しい公開版が生成されるたびに、古いAPI本文を持つスナップショットを残し続けない方針です。リビジョン番号は古い本文の削除後にも再利用しません。

同じ削除操作で管理作品、API情報、発見経路、関連キュー、承認済み構成、旧公開本文を処理し、監査には内部IDと処理結果を残します。API情報を含む公開本文を監査テーブルやデプロイ試行へコピーしません。

## 含まない機能

- P1：Artifact専用ディレクトリ化、Museの定期実行と障害復旧の実証、探索から削除までの全体結合テスト。
- P2：過去作品探索、高速審査UI。
- 新規の探索・審査UI・候補登録・scheduler・強制ロック解除・非常時の公開停止・全サービスの課金/クォータ管理。
- 本番環境の変更や、実データを使うPages・VRChatの動作保証。

P0の局所的な失敗・競合テストはP0の完了確認に含めます。これはP1の全体結合テストを実施済みにするものではありません。

## 保証の境界

**D1とPagesは一つのトランザクションではありません。** D1の削除完了と公開URLの反映完了は別に追跡します。直前認可の後にも新しい公開対象ができる可能性があり、その場合は古い試行の結果で最新版を検証済みにしません。新しい版の公開要求は残ります。

**固定URLの2ファイルには、全クライアントでの同時切替保証がありません。** 同じArtifactで生成しても、利用者が別時刻・別キャッシュから `library.json` と `queue.json` を取得すれば版が混在し得ます。公開JSONに内部版を追加しない今回の契約では、検証地点での両ファイル一致と、すべての利用者の同時整合性を区別します。

**ロックの自動失効はありません。** runner停止後の安全な復旧はP1に残ります。未完了の試行がある場合は、無条件で別試行を進めず停止します。

**Artifactの公開対象はまだルート全体です。** P1の専用ディレクトリ化を先取りせず、workflowは `path: .` を維持しています。そのため、`library.json` と `queue.json` に加えて、非hiddenの `src/`・`scripts/`・`docs/`・`tests/` 等の公開リポジトリのソースもPages Artifactへ含まれます。秘密・設定のローカルコピー・試行文脈はGit対象外またはrunnerの一時領域へ置きます。必要なJSONだけの配信へ絞る変更はP1に残っています。

**期限管理は全コピーの消去を証明しません。** 通常DB上のコピーと旧スナップショットを除去しても、D1のTime Travel、外部キャッシュ、既存VRChatインスタンスに残る情報の即時消去とは異なります。30日・72時間はサービス全体の消去保証ではありません。

**認証済みの直接SQLはAPIの保証外です。** D1管理者や既存オペレーターの直接書込みは、Workerの世代検証や監査を迂回できます。保証はこのAPIを通る操作と、提供DDLに一致するスキーマに対するものです。

## 運用前に残る確認

- YouTube非認証APIデータの更新・削除規定とD1復旧コピーの扱い。Time TravelはFreeで7日、Paidで30日の復旧期間があり、通常DELETEだけで全コピーを消したとは扱えません。[YouTube保持規定](https://developers.google.com/youtube/terms/developer-policies)、[D1 Time Travel](https://developers.cloudflare.com/d1/reference/time-travel/)
- 公開JSONの再提供、編集タイトル、独自ジャンル、VRChatの再生経路の適合性。技術的に配信できることと規約面の確認は別です。[YouTube Developer Policies](https://developers.google.com/youtube/terms/developer-policies)、[公式解説](https://developers.google.com/youtube/terms/developer-policies-guide)
- VRChat側のURL受渡し。公式Udonの `VRCUrl(string)` はEditor時のみであり、JSON文字列から任意URLを実行時に直接生成できると仮定しません。連携先仕様と実機での確認が必要です。[External URLs](https://creators.vrchat.com/worlds/udon/external-urls/)
- 定期処理と無料枠の運用監視。Stage 1は新しい自動起動基盤や長期運転の実証を含みません。

これらを未解決のまま、Stage 1完了を上映システム全体や長期運用の検証完了とは報告しません。
